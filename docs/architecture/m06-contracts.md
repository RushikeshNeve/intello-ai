# M06 contracts: connectors and universal formats (slim)

Frozen 2026-11-19. Lean mode (sanity tests; `docs/execution/TEST_DEBT.md`). First connector: **GitHub** (decision by the user). Builds on m02 (`sources`, documents, versions), m03 (ingestion pipeline, outbox, Celery), m04 (retrieval/citations).

## 1. Principles
1. A connector only **discovers and fetches**. Everything fetched enters through the SAME path as an upload (document + immutable version + `enqueue_ingestion`), so extraction, indexing, deletion and retrieval rules are unchanged. A synced item maps to one document; an upstream change creates a new version; an upstream delete is a logical deletion.
2. **Secrets**: connector tokens are encrypted at rest (AES-256-GCM, key `CONNECTOR_ENCRYPTION_KEY` base64-32B from env, `key_id` stored for rotation), decrypted only inside the sync task, never logged/returned/audited (assert in tests). No token → public access (GitHub public repos).
3. **No network in tests**: connectors talk to an injected HTTP transport; tests use a local fake GitHub server. SSRF rules (§3) apply to every outbound fetch the platform makes on behalf of a user.
4. **Revocation is immediate**: revoking a source (or removing the connector account) denies access to everything it brought in *in the same transaction* (logical deletion of its documents → existing M02/M03/M04 denial paths), wipes the token, cancels queued syncs, and enqueues purge events.
5. **Idempotent sync**: delta replay (same cursor twice, duplicate webhook) creates no duplicate documents/versions (item map keyed by `(source_id, remote_id)` + content sha256 + remote version/etag).

## 2. Connector framework (M06.01.01, .03–.06) — `app/modules/connectors/`
- Port `SourceConnector` (Protocol): `validate(config)`, `discover(cursor: str|None) -> DeltaPage(items: list[RemoteItem], next_cursor: str|None, has_more: bool)`, `fetch(item) -> FetchedItem(bytes, content_type, metadata)`. `RemoteItem(remote_id, path, version_token, size, content_type?, deleted: bool)`. Cursor is opaque, monotonic per source; `discover(None)` = full listing; replaying a cursor is safe. Auth contract documented in the module docstring (token optional; scopes minimal read-only).
- Migration `0009_connectors`: `connector_accounts(id, org_id, provider, label, token_ciphertext bytea null, key_id, created_by, revoked_at, ...)`, `source_syncs(id, org_id, source_id, state queued|running|succeeded|failed, cursor_before, cursor_after, stats jsonb, error_code, started_at, finished_at)`, `source_items(id, org_id, source_id, remote_id, path, document_id, version_token, content_sha256, state active|deleted, last_seen_at)`; extend `sources` (M02) with `connector_account_id`, `config jsonb` (repo owner/name/ref, include globs), `sync_cursor`, `sync_interval_seconds`, `next_sync_at`, `state active|revoked|error`, `webhook_secret_hash`. RLS like other org tables; worker role gets exactly what the sync task needs (decide, document, test via the RLS completeness registry).
- Routes (org admin/workspace admin): `POST /v1/orgs/{o}/workspaces/{w}/sources` (create GitHub source: `{provider:'github', repo:'owner/name', ref?, include?:[glob], token?}`), `GET …/sources`, `GET …/sources/{id}` (state, last sync, item counts; never secrets), `POST …/sources/{id}/sync` (202), `POST …/sources/{id}/revoke`, `DELETE`-like removal = revoke. Webhook: `POST /v1/webhooks/github/{source_id}` verifies `X-Hub-Signature-256` HMAC with the per-source secret, constant-time, 202; invalid → 401 no detail; duplicate delivery id ignored.
- Scheduler: the dispatcher loop enqueues `source.sync.requested` outbox events for sources with `next_sync_at <= now` (interval default 3600 s, min 300 s). Celery `maintenance` task `connectors.sync_source(org_id, source_id)`: claim sync row (one running sync per source), discover → fetch → create/update documents via the shared service function (extract from `upload_service`/finalize the minimal `ingest_remote_item(session, source, item, bytes)` that does what finalize does without presigned upload) → deletions → advance cursor only after all items of the page committed. Sync failures keep the old cursor.
- **GitHub connector** (`github.py`): REST v3 via injected `httpx` client; `discover` = commit-based: first listing uses the git tree of `ref` HEAD (recursive), later syncs use compare `cursor_sha...HEAD` for changed/removed files; filters: size ≤ `CONNECTOR_MAX_FILE_BYTES` (5 MiB), text/code/markdown/pdf/html/csv/xlsx only, `include` globs, skips binaries/vendor dirs; honours rate-limit headers (stop and reschedule with backoff, never hammer); optional token adds `Authorization`. Each item records `repo`, `path`, `commit_sha` in version metadata (M06.02.02).

## 3. Safe URL capture (M06.01.02) — `app/modules/connectors/url_capture.py`
`POST /v1/orgs/{o}/workspaces/{w}/documents/from-url {url, title?}` (editor+). Rules: only `http/https`, no userinfo, ports 80/443 (configurable allowlist), resolve DNS ourselves and **block** loopback/private/link-local/CGNAT/multicast/metadata (169.254.169.254, fd00::/8, ::1, IPv4-mapped IPv6), connect to the validated IP (no DNS rebinding: pin the resolved IP, send `Host`), re-validate on every redirect (max 3, same checks, https→http downgrade refused), size cap (`URL_CAPTURE_MAX_BYTES` 10 MiB, streamed and aborted), 15 s total timeout, content-type allowlist (html/text/pdf), no cookies/auth forwarded, `User-Agent: IntelloBot`. Stores the final URL in version metadata; goes through the same document creation path. Errors are generic (`url_not_allowed`, `fetch_failed`, `too_large`, `unsupported_type`) without echoing internal addresses.

## 4. Formats (M06.02.*) — extend `app/modules/ingestion/processors/` (no pipeline version bump: new content types only)
- **CSV/XLSX (M06.02.01)**: `text/csv`, `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` (dependency `openpyxl` allowed, read-only mode, no formulas evaluated, no external links, max sheets/rows/cells limits). Blocks = row groups with header repeated; new locator kind `cell` `{sheet, row_start, row_end, col_start?, col_end?}` (additive in `contracts.Locator`, chunking keeps it, evidence endpoint returns it). Citations show sheet + cell range.
- **Repository files (M06.02.02)**: source/code files (`text/x-source`, by extension list) → text processor variant with `language` and line locators; version metadata carries repo/path/commit; chunking prefers blank-line/def boundaries but must keep the offset invariant.
- **OCR (M06.02.03)**: `OcrProcessor` contract + capability flag `OCR_ENABLED=false`; images (`image/png|jpeg`) and image-only PDFs yield job state `unsupported` with reason `ocr_unavailable` when disabled (no crash); when enabled a pluggable engine adapter (`OCR_ENGINE=none|tesseract`) returns text + confidence + provenance `{engine, version}`; tests use a fake engine.
- **Audio (M06.02.04)**: `AudioTranscriptProcessor` contract; flag `TRANSCRIBE_ENABLED=false`; output blocks carry `time_start/time_end` locators (new locator kind `time`), size/duration limits; fake engine in tests; disabled ⇒ `unsupported` reason `transcription_unavailable`.
- **Video (M06.02.05)**: capability flag only: `VIDEO_ENABLED=false` ⇒ explicit status `unsupported` reason `video_unavailable`; document capability matrix endpoint `GET /v1/capabilities` → `{ocr, transcription, video, formats:[…]}` (static from settings).
- Status messages: add the new reasons to the ingestion safe-message table (M03 status service) and the web message map is out of scope (lean).

## 6. Lean tests
Happy path per component; one cross-org/workspace check per new route/table (+ RLS registry); SSRF table of blocked addresses and redirect cases; token never in logs/responses/audit; sync delta fixture (new/update/delete) with a fake GitHub; duplicate webhook/cursor replay idempotent; revoke blocks access immediately; each new format extracts with locators; disabled capability gives explicit status.
