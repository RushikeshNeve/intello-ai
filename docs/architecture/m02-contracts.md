# M02 Contracts: object storage, documents, versions, upload, deletion

Status: **frozen for M02** (2026-11-18). Changing anything here needs coordinator approval and a `DECISION_CHANGES.md`
entry. ADRs: 007, 009, 010, 011, 013, 018, 027, 028, 031, 032. Builds on `m01-contracts.md` (principal, tenancy, RLS, authz,
audit, error style, pagination) and `docs/spikes/object-storage.md` (RustFS behaviour).

## 1. Principles
- Bytes live only in the object store (`S3_BUCKET_ORIGINALS`); PostgreSQL owns every id, version, permission and state (ADR-013).
- **Versions are immutable.** A new upload is a new version; nothing overwrites an existing one (ADR-009).
- **The browser uploads and downloads directly** to and from the object store through short-lived presigned URLs. File
  bytes never pass through the API or the web server. The API only issues and verifies.
- **Uploaded content is untrusted.** Never rendered inline from the app origin; the object store is a different origin;
  only an allow-list of types is served inline (§6).
- **Deletion = immediate logical denial** in PostgreSQL; physical purge is asynchronous and later (ADR-018).

## 2. Object keys and storage layer
- Key: `org/<org_id>/doc/<document_id>/<version_id>/original` in `S3_BUCKET_ORIGINALS`. The key **never contains the filename**
  (no traversal, no unicode or length problems). `version_id` is a UUIDv4 generated by the API, so a key is never reused.
- The API uses only what Cloudflare R2 also supports (spike §5): PutObject/GetObject/HeadObject/DeleteObject, multipart,
  SigV4 presigned GET/PUT/UploadPart, `x-amz-checksum-sha256`, path-style addressing locally. No S3 versioning, ACLs, policies or object lock.
- **Port** `app/modules/storage/ports.py` (M02.01.01), a `typing.Protocol` named `ObjectStore`, plus typed errors:
  `put_object(key, data, *, content_type, sha256_b64, if_none_match=True) -> ObjectInfo`,
  `head_object(key) -> ObjectInfo | None` (size, content_type, `checksum_sha256_b64`, etag, last_modified),
  `get_object(key) -> bytes stream`, `delete_object(key) -> None` (idempotent), `presign_put(key, *, content_type, sha256_b64, expires_seconds) -> PresignedRequest`,
  `presign_get(key, *, expires_seconds, filename, content_type, inline) -> str`, and the multipart contract
  (`create_multipart`, `presign_upload_part`, `complete_multipart`, `abort_multipart`, `list_parts`).
  `PresignedRequest = {method, url, headers: dict[str, str], expires_at}`. Errors: `ObjectNotFound`, `ObjectAlreadyExists`,
  `ChecksumMismatch`, `StorageUnavailable`.
- **Adapter** `app/infrastructure/object_storage/` (M02.01.02): boto3, `signature_version="s3v4"`, path-style, `request_checksum_calculation="when_required"`.
  It reads its own settings (`S3_ENDPOINT_URL`, `S3_PUBLIC_ENDPOINT_URL`, `S3_REGION`, `S3_ACCESS_KEY_ID`,
  `S3_SECRET_ACCESS_KEY`, `S3_BUCKET_ORIGINALS`, `S3_BUCKET_ARTIFACTS`, `S3_FORCE_PATH_STYLE`, `S3_PRESIGN_TTL_SECONDS`).
  **Presigned URLs are signed against `S3_PUBLIC_ENDPOINT_URL`** (the host is part of the signature) with a separate client; server-side
  calls (head, get, delete) use `S3_ENDPOINT_URL`. Credentials are never logged or returned.
- A presigned PUT is **bound** to the declared `Content-Type` and `x-amz-checksum-sha256` (both signed headers), so the store rejects a different body.

## 3. Database (migration `0003_documents`, M02.02.01; coordinator-owned migration, `Settings` quota fields)
All tables are org-scoped, `ENABLE` + `FORCE ROW LEVEL SECURITY`, fail-closed policies on `app.current_org_id` exactly like M01
(`org_id = CUR_ORG` for SELECT/UPDATE `USING` and INSERT/UPDATE `WITH CHECK`). The app role gets **no DELETE** on any of them.
All have composite FKs `(workspace_id, org_id) → workspaces(id, org_id)` so a row can't name a workspace of another org.

| Table | Columns | Rules |
|---|---|---|
| `sources` | `id`, `org_id`, `workspace_id`, `kind` (`upload`\|`url`\|`connector`), `name`, `config jsonb default '{}'`, `created_by`, `created_at` | one `kind='upload'` source per workspace (partial unique index); created lazily by the first upload |
| `documents` | `id`, `org_id`, `workspace_id`, `source_id → sources`, `title` (1..255, trimmed), `latest_version_id`, `created_by`, `created_at`, `updated_at`, `deleted_at`, `deleted_by` | `(deleted_at IS NULL) = (deleted_by IS NULL)`; composite FK `(latest_version_id, id) → document_versions(id, document_id)` DEFERRABLE INITIALLY DEFERRED |
| `document_versions` | `id`, `org_id`, `workspace_id`, `document_id → documents`, `version_number` (≥1), `original_filename` (1..255), `content_type` (≤255), `size_bytes` (≥0), `sha256` (`^[0-9a-f]{64}$`), `object_key`, `created_by`, `created_at`, `purged_at` | `unique(document_id, version_number)`, `unique(id, document_id)`, `unique(object_key)`. **Immutable:** a BEFORE UPDATE trigger rejects every change except `purged_at` going NULL → a timestamp (SQLSTATE 42501). Versions are created only at finalize, so there is no "pending" version row |
| `upload_sessions` | `id`, `org_id`, `workspace_id`, `document_id` (reserved for a new document, or the existing one), `version_id` (reserved), `created_by`, `filename`, `content_type`, `size_bytes`, `sha256`, `object_key`, `state` (`pending`\|`finalized`\|`failed`\|`expired`), `failure_code`, `created_at`, `expires_at`, `finalized_at` | `unique(version_id)`; `state` moves only forward (`pending` → one of the others) |

- A **document is created at finalize**, not at session creation, so an abandoned upload leaves no document row. The version number is assigned
  at finalize under `SELECT … FOR UPDATE` on the document row, so concurrent finalizes never share a number.
- **Quota usage** of an org = `SUM(size_bytes)` of versions with `purged_at IS NULL` (deleted-but-unpurged documents still count) + the
  sizes of its non-expired `pending` sessions (so many pending sessions can't bypass the quota).
- Also in M02: a partial unique index on active `resource_grants` (DC-015 follow-up): unique `(resource_type, resource_id, grantee_type, grantee_id, permission) WHERE revoked_at IS NULL`.
- `Settings` (`app/core/config.py`) gains: `UPLOAD_MAX_BYTES` (default 104857600 = 100 MiB), `ORG_STORAGE_QUOTA_BYTES` (5368709120 = 5 GiB),
  `UPLOAD_SESSION_TTL_SECONDS` (3600), `UPLOAD_MAX_PENDING_PER_USER` (20), `DOCUMENT_PURGE_GRACE_DAYS` (7). They are also in `.env.example` and passed to `api` in `apps.yml`.
- New `AuditEventType`s: `document.created`, `document.version.created`, `document.updated`, `document.deleted`.

## 4. Authorization (reuses the M01 policy service; no new actions)
Documents inherit their workspace's roles (`viewer` read; `editor` read+write; `admin` all; org owner/admin are implicit workspace admins) plus
active resource grants on the document (M01.03.03). Concretely:
- **Create a document / new version:** `document.write`. For a new document there is no resource yet, so it is decided from the workspace role alone; for a new
  version of an existing document it is decided with that document's active grants.
- **List / get / versions / content URL:** `document.read`. A user with a read grant on a document but no workspace role sees that document (and only those) in lists.
- **Rename (PATCH):** `document.write`. **Delete:** `document.manage`.
- Non-member of the org → 404; org member with no workspace role and no grant → 404 (`not_workspace_member`); a member lacking the permission → 403 `forbidden`.
  Every denial is audited (`authz.denied`) as in M01.
- Each document in a response carries `permissions: {"write": bool, "manage": bool}` computed for the caller, so the UI can hide actions it can't perform.

## 5. REST API (all `/v1`, auth required; `{ws}` = `/orgs/{org_id}/workspaces/{workspace_id}`)

### Uploads (M02.01.03, M02.01.04)
**`POST {ws}/uploads`**, body `{"filename": str, "content_type": str, "size_bytes": int, "sha256": 64 lowercase hex, "document_id"?: uuid, "title"?: str}`
- `document_id` present = upload a **new version** of that document; absent = a **new document** (`title` defaults to the filename without its extension).
- Validation (422 `invalid_request`): filename 1..255 after sanitizing (strip path separators and control characters, collapse whitespace); `content_type` must look like `type/subtype` (≤255);
  `size_bytes` ≥ 1; `sha256` matches the pattern.
- Quotas, checked in this order: 413 `file_too_large` (`size_bytes > UPLOAD_MAX_BYTES`); 429 `too_many_uploads` (≥ `UPLOAD_MAX_PENDING_PER_USER` pending sessions for this user in this org);
  409 `quota_exceeded` (org usage + `size_bytes` > `ORG_STORAGE_QUOTA_BYTES`). Authorization is checked **before** any of these, so an unauthorized caller learns nothing about quotas.
- **201** `{"upload_id", "document_id", "version_id", "expires_at", "upload": {"method": "PUT", "url", "headers": {"Content-Type": ..., "x-amz-checksum-sha256": base64}}, "limits": {"max_bytes"}}`.
  The client must send the file bytes with **exactly** these headers to `upload.url`. The session expires after `UPLOAD_SESSION_TTL_SECONDS`; the presigned URL after `S3_PRESIGN_TTL_SECONDS` (re-request by creating a new session).

**`POST {ws}/uploads/{upload_id}/finalize`** (no body; the creator only, re-authorized at finalize)
1. Locks the session. If already `finalized` → **200** with the same result (idempotent).
2. Expired (`now > expires_at`) → 410 `upload_expired` (state `expired`).
3. `head_object(object_key)`: missing → 409 `object_missing` (the session stays `pending`, so the client can retry the PUT and finalize again until it expires);
   `size` differs from the declared size → 409 `size_mismatch`; `checksum_sha256` differs from the declared one → 409 `checksum_mismatch`.
   On a mismatch the object is **deleted**, the session becomes `failed` with `failure_code`, and the client must start a new session.
4. In **one transaction**: get-or-create the workspace's `upload` source; create the document (new document) or lock it (new version); assign `version_number`;
   insert the version; set `latest_version_id` and `updated_at`; mark the session `finalized`; write the audit event (`document.created` or `document.version.created`).
- **201** `{"document": Document, "version": Version}` the first time, **200** on a repeat. If a deletion happened meanwhile → 404.
- Sessions of other users, other workspaces or other orgs → 404 `not_found`.

### Documents (M02.02.02), versions (M02.02.03), deletion (M02.02.04)
- **`GET {ws}/documents`**: query `q` (case-insensitive substring of the title or latest filename), `content_type` (exact, or a prefix such as `text/`), `sort` (`updated_at`\|`created_at`\|`title`, default `updated_at`),
  `order` (`asc`\|`desc`, default `desc`; `asc` for `title` by default), `limit` (1..200, default 50), `cursor`. Response `{"items": [Document], "next_cursor": str|null, "can_upload": bool}`.
  Keyset pagination on `(sort key, id)`; deleted documents never appear.
- **`GET {ws}/documents/{document_id}`** → `Document`. **`PATCH`** body `{"title"}` → 200 `Document` (audit `document.updated`, no row/audit when unchanged).
- **`DELETE {ws}/documents/{document_id}`** (`document.manage`) → **202** `{"status": "deletion_requested", "purge_after": ts}`: sets `deleted_at`/`deleted_by`, audit `document.deleted`,
  and from that instant every read, list, version and content-URL call for it returns **404** (also for the owner). `purge_after = deleted_at + DOCUMENT_PURGE_GRACE_DAYS`. A second DELETE → 404.
  Presigned URLs issued before the deletion stay valid until they expire (≤ `S3_PRESIGN_TTL_SECONDS`); physical purge (object delete, `purged_at`) is a later job (M03/M08).
- **`GET {ws}/documents/{document_id}/versions`** → `{"items": [Version], "next_cursor"}` newest first (same pagination). **`GET …/versions/{version_id}`** → `Version`.
- **`GET …/versions/{version_id}/content-url?disposition=inline|attachment`** (default `attachment`) → `{"url", "expires_at", "filename", "content_type", "disposition"}`.
  `inline` is honoured only for allow-listed types (§6), otherwise the response says `attachment`. The URL is a presigned GET with a signed `response-content-disposition`.

### Shapes
- `Document` = `{"id", "org_id", "workspace_id", "title", "created_by", "created_at", "updated_at", "version_count", "latest_version": Version | null, "permissions": {"write", "manage"}}`
- `Version` = `{"id", "document_id", "version_number", "original_filename", "content_type", "size_bytes", "sha256", "created_by", "created_at", "retention": {"status": "current"|"superseded", "purge_after": null}}`
  (`current` = the document's `latest_version_id`; every other version is `superseded`. `deletion_pending`/`purged` are reserved for the purge job and never appear in M02 responses, because deleted documents are 404.)
- Errors are `{"detail": "<code>"}` as in M01: 401 `invalid_token`, 403 `forbidden`, 404 `not_found`, 409 (`quota_exceeded`, `object_missing`, `size_mismatch`, `checksum_mismatch`, `conflict`),
  410 `upload_expired`, 413 `file_too_large`, 422 (`invalid_request` with `errors`, `invalid_cursor`), 429 `too_many_uploads`, 503 `storage_unavailable` (the object store is down).

## 6. Serving content safely
- Inline allow-list: `application/pdf`, `text/plain`, `text/markdown`, `image/png`, `image/jpeg`, `image/gif`, `image/webp`. Everything else (including `text/html`, `image/svg+xml`, scripts, unknown types) is always `attachment`.
- Downloads come from the object-store origin (`S3_PUBLIC_ENDPOINT_URL`), never from the app origin; the filename in `response-content-disposition` is the sanitized RFC 5987 form.
- The browser's CORS access to the object store comes from the bucket CORS rules the init job applies from `API_CORS_ORIGINS` (GET/PUT/HEAD from the web origin only).

## 7. Web (M02.03.x)
- Routes: `/o/{orgSlug}/w/{workspaceSlug}/documents` (library + upload) and `/o/{orgSlug}/w/{workspaceSlug}/documents/{documentId}?v={versionId}` (viewer). All calls go through the BFF (`/api/v1/*`); **file bytes go straight from the browser to `upload.url`**.
- Upload flow: compute SHA-256 in the browser (WebCrypto) → `POST uploads` → `PUT` the file with `upload.headers` using `XMLHttpRequest` (for progress) → `POST finalize`.
  Retry rules: a network error or 5xx on the PUT retries the same session (up to 3 times, backoff) until it expires; a 4xx from the store, `upload_expired` or `checksum_mismatch` starts a **new** session; a finalize `object_missing` re-PUTs.
- The library table keeps `q`, `content_type`, `sort`, `order` and the page cursor in the URL. Show the upload area only when `can_upload`; show delete only when `permissions.manage`.
- The viewer opens a version through `content-url`: PDFs and images inline in a sandboxed frame/element, text and markdown fetched and shown as plain text (**never** rendered as HTML), everything else as a download. An unavailable version (404/410, or a deleted document) shows a calm "not available" state.
