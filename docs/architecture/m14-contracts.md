## M14.05/06

- Egress (`modules/ai/egress.py`): every outbound httpx client (models, embeddings, warmup, github, RushDB, OIDC, OTLP, url capture) calls `egress.check(host, purpose)` (request hook). `EGRESS_ALLOWED_HOSTS` = comma patterns (`host`, `*.suffix`); empty = allow all + warning (dev); the prod list in `.env.prod.example` must include internal hosts. Purpose `url_capture` is allowlist-exempt but all resolved IPs must be global (private/link-local/metadata refused). Logs host + purpose + decision only. A grep test pins the set of client modules: a new client must use egress and be added to it.
- Hosted models: `ai_policies.hosted_models_allowed` (migration 0028, default false, owner-only change via PUT ai-policy); the gateway denies `hosted_not_allowed` for openai without it. `PROVIDER_RETENTION` (openai `store:false`; ZDR / ~30-day abuse retention marked 'verify'); not yet sent on the wire because M08 pins the request keys.
- Tools (`modules/permissions_tools/`): default-deny `ToolRegistry`; `register_tool(name, scopes, requires_confirmation, audit=True, args_schema=PydanticModel)`; `authorize(user, workspace, run, tool, args)` returns allow/deny/needs_confirmation (registered, enabled in `RunContext.enabled` by the orchestrator, user scopes, budget, strict args schema); audit is ids only. The registry is empty; model/retrieved text never reaches it. New tool (e.g. create GitHub issue): register in its own module with a scope and confirmation=True for writes, enable it per run in the orchestrator, execute only after allow/confirmed, add a test.
