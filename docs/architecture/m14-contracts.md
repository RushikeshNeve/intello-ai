# M14 contracts: AI firewall and security

## M14.01/03 Input guard and output guard
- Table `firewall_policies` (migration 0023, RLS by org, app CRUD, worker SELECT): modes `input_user`, `input_evidence` in off|flag|block, `output` in off|flag|block|redact, `threshold` 0.05-1.0. No row = all off. API `GET/PUT /v1/orgs/{org}/firewall-policy` (members read, owner/admin write, other org 404); audit `org.firewall_policy.updated` (modes only). UI: AI firewall card in settings.
- `firewall/input_guard.py`: layered rules (injection phrases, prompt exfiltration, role play, role tokens, fence forgery, bidi/invisible/tag Unicode, encoded markers) on normalized text plus pluggable `set_classifier(fn(text)->score)` (no-op default). Hit = score >= threshold.
- Hooks (`firewall/hooks.py`, called from `ai/chat.py`, `research/runtime.py`): user hit in block -> run fails `input_blocked`, model never called; hostile evidence chunk dropped (counted), run continues; flag only records.
- `firewall/output_guard.py`: per-org canary appended to the system scaffold only while output mode != off (prompt text and `PROMPT_VERSION` unchanged), 6-word scaffold shingle echo, secret patterns, citation markers/ids outside the offered evidence. `StreamGuard` holds back 96 chars so blocked text is never flushed; block -> run fails `output_blocked`; redact replaces secrets (and `firewall.pii.redact` when that module exists; guarded import), unredactable findings block.
- Fail-safe: guard error in block mode blocks (user: refuse, chunk: drop, output: withhold); in flag/off it passes. Policy load failure reads as off.
- Metadata: `chat_runs.model.firewall` holds counts and rule ids only, never text.

## M14.02 Document scanning
Ingestion scan runs inside `DefaultPipelineRunner` between extract and chunk (`modules/ingestion/scan/`). It is not a checkpointed stage (`STAGES` is unchanged): it re-runs idempotently on resume (findings replaced per version in one transaction).
- Policy `document_scan_policies` (workspace row, else org default, else `flag`): `off` | `flag` (index, show findings) | `quarantine` (a `high` finding sets `knowledge_revisions.state='quarantined'`; no chunks, embeddings, index writes or publication; job ends `succeeded`/`quarantined`).
- Fails closed: scanner error in `quarantine` mode raises `RetryableJobError("scan_failed")`; in `flag` mode indexing proceeds.
- `document_findings` (rule, severity, page/offset/entry location, preview <= 40 chars redacted; FORCE RLS, admin read, worker write; unique per version/rule/location). Rules: hidden_instruction, invisible_unicode, hidden_text (HTML), suspicious_link, office_macro, embedded_executable, embedded_object, pdf_active_content. Not available from extractors: PDF white/tiny text, text-to-visible mismatch.
- API (workspace admin = `workspace.update`): `GET/PUT .../scan-policy`, `GET .../documents/{d}/findings`, `GET .../quarantine`, `POST .../quarantine/{d}/release` (records `document_scan_releases`, definer `ingest_release_quarantine` re-queues the job), `DELETE .../quarantine/{d}` (normal deletion; also removes findings).
- Non-admins see a quarantined document's ingestion state as `processing` (status/jobs mapping). ORM `REVISION_STATES` is unchanged (an existing test pins it); migration 0024 is the authority for the `quarantined` CHECK.

## M14.07 Abuse protection and canary documents
- Tables (migration `0025_abuse_canaries`, FORCE RLS by org): `security_events` (kind `abuse_anomaly|canary_hit`, severity, `counts` jsonb, run_id, document_id; ids and counts only, never text), `canary_documents` (flag kept out of `documents`), `abuse_settings` (per-org action `off|flag|throttle|block` + thresholds).
- `firewall/abuse.py`: `guard(sessions, org, user, kind, document_ids=)` counts search/chat/evidence_read/export and distinct documents in a sliding window (Redis zsets, in-process fallback; fails open). Hooked after the membership check in search, chunk evidence, chat run creation and research export.
- Crossing a threshold records ONE event per user per window (Redis/memory gate plus DB check) and an audit event; `throttle` answers 429 `abuse_throttled` while over the threshold, `block` for `block_seconds`. Defaults: flag, 300 s window, 120 search, 60 chat, 200 reads, 20 exports, 150 distinct docs.
- Canaries: an admin marks a document; its audience is nobody, so ANY retrieval, evidence read or chat citation raises a `high` `canary_hit` (deduped 60 s per user and document). `abuse.canary_document_ids(session, org)` MUST be used to exclude canaries from eval and analytics counts.
- Admin API `/v1/orgs/{org}/security/{events, events/{id}/acknowledge, abuse-settings, canaries}`: owner/admin only (member 403, outsider 404). Web: `AbusePanel` in settings.
- Runbook: place a canary in a locked workspace nobody is granted, with a believable title; treat any event as an incident (security-incident.md section 5).

## M14.08 Encryption and key management
- Envelope encryption (`app/core/crypto`): `KeyProvider` (KEK) wraps per-org DEKs in `tenant_keys` (0026: id, org_id, kek_id, wrapped_key, state active|retired, FORCE RLS; app/worker SELECT+INSERT only; one active per org). `LocalFileKeyProvider` (`MASTER_KEY_FILE`/`MASTER_KEY`, `MASTER_KEY_ID`, `MASTER_OLD_KEYS`); AWS/GCP KMS and Vault are a documented stub (`KEY_PROVIDER`). Unset master key = M06 single-key behaviour unchanged.
- Sealed value: AES-256-GCM, key id `dek:<uuid>`, aad = `ukos-dek-v1|org_id|row id`; wrap aad = `ukos-kek-v1|org_id|dek_id`.
- Connector tokens + webhook secrets use `connectors.crypto.secret_cipher(session, org, settings)`: dual read of legacy `k1` rows; the sync re-seals a legacy token lazily (worker gains UPDATE(token_ciphertext, key_id)); `rotate-keys.sh reencrypt` migrates the rest.
- `scripts/ops/rotate-keys.sh kek|dek --org|reencrypt|verify|shred --org --yes` (dry run + verify around each change; batched, SKIP LOCKED, resumable, idempotent). Shred = delete the org's DEKs; legacy rows are not covered until re-encrypted.
- Backups: `BACKUP_ENCRYPTION_KEY_FILE` -> `payload.tar.enc` (openssl aes-256-cbc pbkdf2 200k; manifest `encrypted: true`, `key_id` = label or key fingerprint, payload sha256); restore.sh decrypts to a temp dir, then the normal manifest verify (plaintext hashes = integrity).
- Not done: memory/capture text columns stay plaintext (FTS/search and the evidence pipeline read them; encrypting them would break retrieval for little gain over disk encryption). Compose files do not yet pass `MASTER_*` to api/worker (mount the key file as a secret; follow-up).

## M14.04 PII and secret detection
- API (`app.modules.firewall.pii`): `detect(text)->[Finding(type,start,end,confidence)]`, `redact(text, mode='mask'|'placeholder'|'hash', policy)->RedactionResult(text, counts_by_type)`; `Redactor` keeps stable per-request placeholders (`[EMAIL_1]`) and `restore()`. Guards import `redact` lazily. Matched values are never logged or in reprs.
- Detectors: email, phone (E.164-ish/US), IPv4/6, card (Luhn), IBAN (mod-97), US SSN, Aadhaar (Verhoeff, bare digits need context), PAN, passport (context word), JWT, AWS/GCP/GitHub/Slack/OpenAI/Anthropic/Stripe keys, PEM private keys, high-entropy values after key/secret/token/password. Types in `SECRET_TYPES` vs `PII_TYPES`.
- Outbound: `ai_policies.pii_outbound` off|redact|block (default off), `pii_restore` (default false), `pii_secrets` block|redact (default block). `get_chat_model` wraps the hosted adapter in `PiiGuardedChatModel` only when enabled; local path untouched. Mapping never leaves the process. Block raises `PiiBlocked` (run error code `pii_blocked`, counts only).
- Ingestion: `workspace_pii_settings(record_counts, mask_indexed)` default off, migration `0027_pii_policy`; `ingest.scan_text` returns counts by type only. NOT yet wired into the pipeline: M14.02 should call `load_workspace_settings`/`scan_text` and store counts as a finding.
- Known limits: person names and postal addresses are not detected; heuristics (phones, IPv4, entropy) can false-positive/negative; no non-Latin digit handling; outbound redaction covers prompt messages only, not provider-side tool payloads.
