ADRs: 008, 009, 013, 014, 015, 016, 018, 020, 036, 037, 038, 040, 048. Builds on `m01-contracts.md` (tenancy, RLS, authz, audit,

## 1. Principles
- **PostgreSQL is the truth.** Jobs, leases, checkpoints, revisions and the *publication pointer* live in PostgreSQL. Redis/Celery only deliver
  wake-ups and may lose or duplicate any message; RushDB holds a *derived, rebuildable* index.
- **At-least-once delivery, idempotent execution.** Every stage can run twice with the same result. Duplicate delivery, a crash at any line, and a
  stale worker waking up after its lease expired must never lose work, duplicate knowledge or publish twice.
- **Immutable derived revisions (ADR-016).** Ingesting a document version produces one *knowledge revision* with a **deterministic id**; a re-run
  reuses it. A new pipeline or embedding version creates a new revision; old ones are superseded, never edited.
- **Publication barrier (ADR-015).** A revision becomes searchable only through one atomic PostgreSQL pointer swap after it is complete and
  validated. A half-indexed revision is never retrievable. Retrieval **must revalidate** every candidate against the PostgreSQL pointer.
- **Untrusted input.** Extracted text, HTML, PDFs and model responses are untrusted. No processor fetches a URL, runs a script or executes content.
  Document text is never logged; errors are stored as stable codes plus a redacted, truncated detail.

## 2. Trigger and pipeline
`POST …/uploads/{id}/finalize` (M02) creates the version; **in that same database transaction** it calls `enqueue_ingestion(session, version)`
(`app/modules/ingestion/jobs.py`), which inserts an `ingestion_jobs` row (`queued`), an `ingestion_job_events` row (`queued`) and an
`outbox_events` row (`ingestion.job.queued`). If the finalize transaction rolls back, none of them exist (transactional outbox).

```
finalize txn ──► outbox ──► dispatcher ──► Celery task ingest.run_job(job_id) ──► worker:
   claim (lease) → extract → chunk → embed → index → validate → publish(pointer swap + flag flip) → succeeded
```
Stages run in this order inside one job. Each stage is **checkpointed** (§6): on a retry, completed stages whose input fingerprint still matches are skipped.
Content types supported in M03: `application/pdf`, `text/plain`, `text/markdown`, `text/html`. Any other type ends the job as `unsupported`
(terminal, not an error; M06 adds more processors). Scanned PDFs with no extractable text end as `unsupported` with code `no_text_extracted` (OCR is M06).

**Deterministic ids.** `NS = uuid5(NAMESPACE_URL, "https://intello.ai/ingest")`. `revision_id = uuid5(NS, f"{version_id}:{PIPELINE_VERSION}:{embedding_space_id}")`;
chunk record id = `uuid5(revision_id, f"chunk:{chunk_index}")`. `PIPELINE_VERSION` is the string `"1"` (bump it when extraction/chunking semantics change).

the M01 fail-closed policies on `app.current_org_id` (no `TO` clause, so they bind every role), no DELETE grants.

## 4. Database roles and cross-tenant functions
RLS is fail-closed on `app.current_org_id`, but a worker must *discover* work across orgs. Two roles, no `BYPASSRLS` anywhere:
- `ukos_app` (API): `SELECT`/`INSERT` on `ingestion_jobs`, `ingestion_job_events`, `outbox_events` (finalize and deletion enqueue work); `SELECT` on `ingestion_checkpoints`, `knowledge_revisions`, `document_publications`.
- **`ukos_worker`** (new, `LOGIN NOSUPERUSER NOBYPASSRLS`, created by the migration from `POSTGRES_WORKER_PASSWORD`): `SELECT`/`UPDATE` (column-limited) and `INSERT` on the ingestion tables above, `SELECT` on `documents`, `document_versions`, `workspaces`, `organizations`.
  Once it has set `app.current_org_id` to a job's org, every query runs under the normal RLS policies.
- **Cross-org discovery only through `SECURITY DEFINER` functions** (owner `ukos_admin`, `search_path = pg_catalog, public, pg_temp`, `REVOKE ALL … FROM PUBLIC`, `EXECUTE` only to `ukos_worker`):
  - `ingest_claim_job(p_job_id uuid, p_owner text, p_lease_seconds int)` → 0 or 1 row `(job_id, org_id, workspace_id, document_id, version_id, revision_id, attempts, lease_epoch)`: claims *that* job if `state='queued' AND run_after <= now()` using `FOR UPDATE SKIP LOCKED`, sets `running`, `lease_owner`, `lease_expires_at = now()+lease`, `lease_epoch = lease_epoch+1`, `attempts = attempts+1`, `heartbeat_at`, writes a `started` event. Already running/finished/not yet due → 0 rows (a duplicate delivery is a no-op).
  - `ingest_reap_expired_leases(p_backoff_base int)` → count: every `running` job with `lease_expires_at < now()` becomes `queued` (`run_after = now() + backoff`) and gets an `ingestion.job.queued` outbox row, or `dead` if `attempts >= max_attempts`; writes events.
  - `outbox_fetch_batch(p_limit int)` (rows with `dispatched_at IS NULL AND available_at <= now()`, `FOR UPDATE SKIP LOCKED`, locks held until the caller's transaction ends), `outbox_mark_dispatched(p_ids uuid[])`, `outbox_mark_failed(p_id uuid, p_error text, p_retry_in_seconds int)`.
  - `knowledge_next_reconcile_batch(p_limit int, p_older_than_seconds int)` → `(org_id, document_id, revision_id)` of publications whose `reconciled_at` is NULL or older than the threshold (marks them), for the drift sweeper (§9).
- Env: `POSTGRES_WORKER_USER` (default `ukos_worker`), `POSTGRES_WORKER_PASSWORD` (`change-me-*`), `DATABASE_WORKER_URL`. The role is created by the **migration** (not the init script, which only runs on an empty volume), from `-x worker_password=` or the env var; `api-migrate` receives it.

## 5. Outbox and dispatcher (M03.01.02)
`python -m app.workers.dispatcher` is a long-running loop (its own compose service `dispatcher`, connecting as `ukos_worker`): every `OUTBOX_POLL_SECONDS`, in **one transaction**
`outbox_fetch_batch(n)` → for each row send the Celery task (`ingestion.job.queued` → `ingest.run_job(job_id)`; `knowledge.revision.published`, `document.deleted`, `knowledge.reconcile` → `knowledge.handle_event(event_id)`)
→ `outbox_mark_dispatched` → commit. A crash after sending but before commit re-sends the row (at-least-once); a broker outage leaves rows undispatched and they go out when it returns; a failing row is
rescheduled with exponential backoff via `outbox_mark_failed`. The same loop runs the lease reaper every `INGEST_REAP_INTERVAL_SECONDS` and the reconcile sweeper every `INGEST_RECONCILE_INTERVAL_SECONDS`.

## 6. Execution (M03.01.03, M03.01.04)
- **Celery** (`app/workers/celery_app.py`): broker `CELERY_BROKER_URL` (Redis db 1). `acks_late=True`, `task_reject_on_worker_lost=True`, `worker_prefetch_multiplier=1`, JSON serializer only, tasks carry only ids. Queues: `ingest` (the job task; concurrency `INGEST_CONCURRENCY`, default 2) and `maintenance` (event handlers). Task routes are explicit; unknown task names are rejected.
  Time limits: soft `INGEST_TASK_SOFT_LIMIT_SECONDS` (default 900) and a hard limit above it.
- **Job runner** (`ingestion/execution.py`): `claim → [stage…] → finish`. The runner heartbeats every `INGEST_HEARTBEAT_SECONDS` (extends `lease_expires_at`, sets `heartbeat_at`) from a background thread while a stage runs.
  **Fencing:** every state-changing write after the claim (checkpoint, state, publication) is conditioned on `lease_owner = me AND lease_epoch = <my epoch> AND state = 'running'`; a worker that lost its lease gets 0 rows and must stop (raises `LeaseLost`) without publishing. Before each stage the runner also checks the job and its document are not `cancelled`/deleted.
- **Retry policy:** a *transient* error (storage/RushDB/embedding server unavailable, timeouts) → job back to `queued` with `run_after = now() + INGEST_RETRY_BASE_SECONDS · 2^(attempts-1)` (cap 1 h, ±20 % jitter) and an outbox row; a *permanent* error (corrupt file, unsupported structure, size/page limits) → `dead` immediately (no retries) with its code; attempts exhausted (`INGEST_MAX_ATTEMPTS`, default 5) → `dead`. `dead` jobs stay visible; a manual retry (§11) creates a fresh job for the same version.
- **Checkpoints** (`ingestion/checkpoints.py`, M03.02.04): `stage_fingerprint = sha256(stage_name ‖ input_sha256 ‖ parameters)`. A stage is skipped when its checkpoint is `completed` with the same fingerprint and (for artifact stages) the artifact object exists with the recorded sha256; otherwise it is re-run and the checkpoint upserted. Artifacts live in `S3_BUCKET_ARTIFACTS` under `org/<org>/doc/<doc>/<version>/<pipeline_version>/<stage>.<ext>` (immutable per fingerprint: written with `If-None-Match`, a duplicate write of identical bytes is accepted).

## 7. Stage data contracts (M03.02.01–.05)
- **`ExtractedDocument`** (`ingestion/contracts.py`, JSON artifact `extracted.json`): `{schema_version, modality: "pdf"|"text"|"markdown"|"html", source: {version_id, sha256, content_type, byte_size}, processor: {name, version}, language?: str, blocks: [Block], stats: {pages?, chars}}`.
  `Block = {block_id (stable: "b{index}"), kind: "heading"|"paragraph"|"list"|"table"|"code"|"quote", text, level?: int, locator: Locator}`;
  `Locator = {kind: "page"|"offset"|"line", page?: int (1-based), char_start: int, char_end: int, line_start?: int, line_end?: int, section_path?: [str]}` — offsets are into the **block's normalized text stream** (the concatenation of all block texts joined by `\n\n`), so every chunk can be mapped back to a page, a heading path and exact offsets.
- **Processors** (`ingestion/processors/`, one module per format + a registry keyed by content type): plain text (encoding detection via `charset-normalizer`, BOM handling, NUL stripping), Markdown (ATX/Setext headings → sections, fenced code kept intact, front-matter ignored), HTML (`beautifulsoup4`, scripts/styles/comments/forms removed, headings/lists/tables kept as text, **no network, no resource loading**), PDF (`pypdf`, text per page, page numbers in locators; hard limits: `INGEST_MAX_PDF_PAGES` (2000), `INGEST_MAX_EXTRACT_BYTES` (50 MiB of text), nesting depth limits; encrypted or corrupt → permanent error `pdf_unreadable`; no text at all → `no_text_extracted`). Processors are pure functions `(bytes, content_type) -> ExtractedDocument` with no I/O. Permitted error codes are a closed set: `unsupported_type`, `no_text_extracted`, `pdf_unreadable`, `encoding_unreadable`, `too_large`, `too_many_pages`, `malformed_input`.
- **Normalization and chunking** (`ingestion/chunking.py`): Unicode NFC, collapse whitespace, strip control characters, keep paragraph breaks. Chunks are cut on block/sentence boundaries to `INGEST_CHUNK_TARGET_CHARS` (default 1800, ≈ 450 tokens; hard max 2400) with `INGEST_CHUNK_OVERLAP_CHARS` (200) of overlap **inside** a long block only. Deterministic: the same `ExtractedDocument` always yields byte-identical chunks.
  `Chunk = {chunk_index, chunk_id (uuid5), text, token_estimate (= ceil(len(text)/4)), content_hash (sha256 of text), locators: [Locator] (the blocks it spans), heading_path: [str], page_start?: int, page_end?: int}`. Empty/whitespace chunks are never emitted. A document must yield ≥ 1 chunk or ends as `no_text_extracted`. Cap: `INGEST_MAX_CHUNKS` (20,000) → `too_large`.
- **Embeddings** (`app/modules/ai/embeddings/`, M03.02.05): `EmbeddingModelSpec {provider, model_id, dimensions, query_prefix, document_prefix, max_input_chars, spec_version}` registry; default spec = `google/embedding-gemma-300m`, 768 dimensions, query prefix `"task: search result | query: "`, document prefix `"title: none | text: "`, context 2048 tokens (from `docs/spikes/local-models.md`).
  `embedding_space_id = "e" + sha256(f"{model_id}|{dimensions}|{query_prefix}|{document_prefix}|{spec_version}")[:12]`; changing any of them is a **new space** (ADR-020), hence a new revision and a new RushDB vector index (`chunk-emb-<space_id>`), and requires re-embedding. Client for any OpenAI-compatible `/v1/embeddings` server (`AI_BASE_URL`, `AI_EMBEDDING_MODEL`, `AI_EMBEDDING_DIMENSIONS`, optional `AI_API_KEY`); batches of `INGEST_EMBED_BATCH_SIZE` (16); bounded retries with backoff on 5xx/timeouts/connection errors (→ transient); **dimension mismatch, non-finite values, a wrong number of vectors or an empty response are errors** (never stored); token usage is counted client-side (LM Studio reports 0). The embed artifact `embeddings.f32` is `N × D` little-endian float32, row `i` ↔ chunk `i`.

## 8. RushDB knowledge index (M03.03.01, M03.03.02; DC-009, spike §7)
- **One adapter**, `app/infrastructure/rushdb/repository.py`, the only code that talks to RushDB. `RUSHDB_URL` + `RUSHDB_TOKEN` are read **only** by it and only the API/worker containers receive them. The tenant scope is `org:<org_id>` sent as both `X-RushDB-Tenant` and `context.scope`; an `OrgScope` object can only be obtained from `validated_org_scope(session, org_id)`, which checks the org exists and is live in PostgreSQL first (an unknown scope would silently create an empty tenant). The adapter never accepts a scope from a request body.
- **Records:** label `Chunk` with properties `org_id, workspace_id, document_id, version_id, revision_id, chunk_index, text, token_estimate, content_hash, locators (JSON string), heading_path (JSON string), page_start, page_end, embedding_space_id, published (bool), created_at`; the vector is bound to index `chunk-emb-<space_id>` (property `embedding`); a BM25 text index `chunk-text` on `text` (created per tenant, polled until `ready`). Default write `options: {}` (never `suggestTypes: false`). Records are written with **explicit ids and `merge`** (so retries and duplicate tasks overwrite, never duplicate).
- **API (sync, httpx):** `ensure_indexes(scope, space)`; `upsert_chunks(scope, revision, chunks, vectors)` (unpublished: `published=false`; batches ≤ 100); `count_chunks(scope, revision_id)`; `set_published(scope, revision_id, flag)` (idempotent, batched); `delete_revision(scope, revision_id)`; `delete_document(scope, document_id)` (the §3.9 purge procedure, idempotent); and the search contract M04 builds on: `search_keyword`, `search_vector`, `search_hybrid(scope, query, filters)`, where `SearchFilters(workspace_ids)` is mandatory and the adapter **always** adds `published = true` and the workspace predicate itself, in one place (no caller composes a predicate), to the root and to every related block. Hits carry `chunk_id, document_id, version_id, revision_id, workspace_id, score, locators` so the caller **revalidates against PostgreSQL**. Never `query.text`, never `query.record`, no user-supplied statements.
- Backups use cold volume snapshots; after any restore, re-create the text indexes (the restore smoke already checks BM25).

## 9. Publication barrier (M03.03.03) and reconciliation
`knowledge/publication.py`. Sequence (stages `validate` then `publish`):
1. **validate:** the revision's chunks in RushDB are counted (`== chunk_count`), and a content fingerprint of the stored chunks' `content_hash` values (ordered) equals the one computed from the chunks artifact. Success → `knowledge_revisions.state = 'ready'`.
2. **publish (one PostgreSQL transaction, fenced):** lock the job row (`FOR UPDATE`) and verify `lease_owner`, `lease_epoch`, `state='running'`; lock the document's publication row; if the document or version was deleted → abort as `cancelled`; if the existing published revision belongs to a **newer** `version_number` → mark this revision `superseded` and finish (an older version finishing late never regresses the pointer); otherwise upsert `document_publications` to this revision (`previous_revision_id` = old), mark the old revision `superseded` and this one `published`, write audit `document.version.indexed`, and insert outbox `knowledge.revision.published`. **Commit.** This commit is the publication.
3. **Flag flip (after commit, idempotent):** `set_published(new, true)` then `set_published(old, false)`; the job ends `succeeded`. If the worker dies between 2 and 3, the `knowledge.revision.published` event handler or the reconcile sweeper completes it. For a short window both revisions may be flagged; that is safe because **retrieval revalidates every hit's `revision_id` against `document_publications`** and drops stale ones.
4. **Purge of superseded revisions:** the `knowledge.revision.published` handler deletes the old revision's chunks from RushDB (`delete_revision`) after the flip and marks it `purged`.
- **Reconciliation** (`knowledge.reconcile` handler, fed by `knowledge_next_reconcile_batch`): for a document, compare the pointer with RushDB (published chunks of exactly the pointed revision; none for any other revision) and repair by re-applying `set_published` / `delete_revision`; if the pointed revision's chunks are missing entirely, create a new ingestion job for that version (self-healing). Always idempotent; sets `reconciled_at`.
- **Deletion** (outbox `document.deleted`, emitted by the M02 delete endpoint in the same transaction): the handler cancels queued/running jobs (`cancelled`), deletes the document's chunks from RushDB, marks its revisions `purged`, removes the pointer. Access was already denied in PostgreSQL at delete time (ADR-018); the object-store purge stays a later job.

## 11. API additions (M03.03.04; M02 shapes extended additively)
- `Document` (and the list items) gains `ingestion: {"state": "none"|"queued"|"processing"|"indexed"|"failed"|"unsupported", "stage": str|null, "updated_at": ts|null, "error_code": str|null}` for the document's **latest version** (`none` = no job yet, e.g. uploaded before M03). Mapping: job `queued` → `queued`; `running` → `processing`; `succeeded` with the revision published → `indexed`; `dead` → `failed`; `unsupported` → `unsupported`.
- `GET {ws}/documents/{id}/ingestion` → `{state, stage, attempts, max_attempts, updated_at, error_code, revision_id, published_at}` (`document.read`).
- `POST {ws}/documents/{id}/ingestion/retry` (`document.write`) → 202 `{job_id}`: creates a new job for the latest version if its job is `dead` or `none` (409 `conflict` if one is active; idempotent per revision).
- **Status stream (SSE)** `GET {ws}/documents/{id}/ingestion/events` and `GET {ws}/ingestion/events` (workspace role holders only): `text/event-stream`; first an `event: snapshot` with the current persisted state, then `event: job` messages with `id: <ingestion_job_events.seq>`; honours `Last-Event-ID` (replays later events, bounded to 500, else a fresh snapshot); `: keep-alive` comment every 15 s; the server closes after 5 minutes and the client reconnects. State always comes from PostgreSQL, so a reconnect never depends on memory. Only events for documents the caller may read are sent.
- A one-time **backfill** (`python -m app.workers.backfill`) enqueues ingestion for documents that have no job/revision (documents uploaded during M02).

## 12. Security checklist (tested in M03.03.05 and the M03 gate)
Org/workspace ids on every record; scope derived server-side and validated in PostgreSQL; the worker role cannot read another org's rows except through the five definer functions (which return ids only); `RUSHDB_TOKEN` absent from the web container and from logs; no document text or presigned URL in logs or error details; processors have hard size/page/depth caps and no I/O; a stale worker can't publish (fencing); an older version can't overwrite a newer publication; deleted documents are never (re)indexed; superseded and deleted revisions are purged from RushDB; the `published` flag is only a pre-filter and retrieval revalidates against `document_publications`.
