# M07 contracts: memory, research, advanced UX (slim)

Frozen 2026-11-20. Lean mode (sanity tests; `docs/execution/TEST_DEBT.md`). **Functional UI only: visual redesign is milestone M09** (`docs/ui-spec/*`); light/dark here is a minimal CSS-variable switch.
Builds on m04 (retrieval/chat/verification/citations), m05 (graph), m06 (sources).

## 1. Principles
1. **Memory is opt-in and evidence-bound.** Only `approved`, unexpired memories whose evidence still revalidates (documents live, workspace in scope) are ever used; a *suggestion* is never a fact (assert in tests). Memory is private to its owner by default (`visibility: private|workspace`; workspace-visible requires workspace admin approval).
2. **Research is bounded and recoverable.** Limits are enforced before work starts and during (max sub-queries 6, max evidence chunks 60, max model calls 12, wall-clock 10 min, scope = a workspace subset the user may read). State is persisted per step; a restarted worker resumes at the first incomplete step; nothing runs unbounded.
3. **Every sourced statement in a report carries a citation** to an original chunk, re-resolved at read time (same rules as chat: `resolve_citation`, `verify`). Statements failing verification are withheld/flagged exactly like chat.
4. Everything is org/workspace-scoped with RLS; creator-private by default; no text of questions/memories/reports in logs or audit (ids, counts, codes only).

## 2. Data (migration `0010_memory_research`, owned by the backend agent; chain after the latest head on main)
- `memories(id, org_id, workspace_id null, owner_id, visibility private|workspace, kind fact|preference|decision, statement text ≤ 2000, state suggested|approved|rejected|expired|invalidated, evidence jsonb[] ({chunk_id, document_id, version_id, workspace_id}), source text user|chat|research, source_ref uuid null, expires_at null, approved_by null, approved_at null, invalidated_reason null, created_at, updated_at)`; evidence required (≥ 1) except `kind=preference`.
- `research_sessions(id, org_id, workspace_id null, created_by, question text ≤ 2000, state planned|running|completed|failed|cancelled, plan jsonb, limits jsonb, usage jsonb, error_code null, lease_owner, lease_expires_at, lease_epoch, created_at, started_at, finished_at)`.
- `research_steps(id, org_id, session_id, seq int, kind plan|search|synthesize|report, query text null, state pending|running|done|failed, result jsonb, started_at, finished_at)` unique (session_id, seq); `research_reports(session_id pk, org_id, sections jsonb [{heading, statements:[{text, citations:[Citation]}]}], verification jsonb, created_at)`.
- RLS: owner-private like chat threads (`owner_id/created_by = app.current_user_id`) plus workspace-visible memories readable by members; worker role gets what the runtime needs (decide, document, register in the RLS completeness suite). Outbox event types `research.session.queued` (new) reuse the chat/ingest dispatcher patterns; Celery queue `research` (declare it; add to worker `-Q`).

## 3. Memory API (M07.01.01–.03) — `app/modules/memory/`
`POST /v1/orgs/{o}/memory/suggestions {statement, kind, workspace_id?, evidence:[{chunk_id,document_id,version_id}], expires_at?, visibility?}` → 201 memory (state `suggested`); evidence is validated server-side (each chunk exists in the artifact store for that version and the user may read that document). `GET /v1/orgs/{o}/memory?state=&limit=&after=` (own + workspace-visible), `GET /memory/{id}` (with evidence re-resolved: `evidence_status ok|stale` per item), `POST /memory/{id}/approve`, `POST /memory/{id}/reject`, `DELETE /memory/{id}` (owner). Workspace visibility needs workspace admin to approve. Chat integration (`GRAPH`-style hook, flag `MEMORY_ENABLED=true`): approved + valid memories relevant to the question (lexical/embedding match, ≤ 5) are added to the prompt as a separate fenced "memory" block and cited as `[mN]`-style items resolving to their evidence chunks; stale ones are skipped. **Invalidation**: handler for `document.deleted`, source revocation, and version supersede marks memories whose evidence document is gone `invalidated` (reason `evidence_deleted|source_revoked|evidence_superseded`); also re-checked lazily at read/use time. Expiry sweep sets `expired`. Chat may *propose* a suggestion from an answer (`POST …/memory/suggestions` by the UI "Remember this" button) but never auto-approves.

## 4. Research API (M07.02.01–.03) — `app/modules/research/`
`POST /v1/orgs/{o}/research {question, workspace_ids?, limits?}` → 202 `{id, state:'planned'}` (limits can only lower the defaults); `GET …/research/{id}` → `{id, question, state, plan:{subqueries:[…]}, steps:[{seq,kind,query,state}], usage, error_code?, message?, report?}`; `GET …/research?limit&after`; `POST …/research/{id}/cancel`. Worker task `research.run(session_id)` (claim/lease/fence like chat): plan (local LLM JSON, validated, ≤ limit sub-queries, unknown fields dropped) → per sub-query retrieval (`gather`/`finish`, graph hook if enabled) → per sub-query synthesis (`build_prompt` + model + `verify`) → report assembly (sections = sub-queries; statements = kept claims with citations). Resume after crash from the first non-`done` step (idempotent: step results stored; no duplicate model calls for done steps). Safe `error_code`s as chat (`model_unavailable`, `policy_denied`, `search_unavailable`, `timeout`, `limit_exceeded`, `internal_error`). Reports are read through the same citation re-resolution as chat; export `GET …/research/{id}/export?format=md` (markdown with footnote-style sources, no raw HTML).

## 5. Web (M07.01.04, M07.02.04, M07.03.01–.03) — functional only
- `/o/{org}/memory`: lists suggestions/approved/rejected, preview of evidence (links to the evidence viewer), approve/reject/delete; "Remember this" button on chat answers.
- `/o/{org}/research`: start form (question, scope, limits shown), session list, session page polling `GET research/{id}` every 2 s until terminal (steps list, report with citations → evidence viewer, export link, cancel).
- Command palette (Ctrl/⌘+K): navigate orgs/workspaces/search/chat/memory/research/graph/documents, run "new chat"/"search for …", fully keyboard operable, focus trap, Esc closes.
- Locator viewers: evidence viewer handles `Locator.kind = line` for code (highlight exact line range, line numbers) and `cell` for sheets (render sheet grid window with the cited cell range highlighted; data from the chunk/evidence endpoint or the document preview); fallbacks to chunk text.
- Theme: `light|dark|system` toggle via CSS variables + `prefers-color-scheme`, `prefers-reduced-motion` respected, responsive panels at ≥ 320 px. **No visual redesign** (M09).

## 6. Settings

## 7. Lean tests
Happy path per route; one cross-user + one cross-org check per new table/route (+ RLS registry); suggestion never used by chat until approved; invalidation on document delete; expiry; research limits enforced, resume after worker kill (no duplicate step results), cancel; every report statement has a resolvable citation; unsupported statements withheld; export has no HTML; web vitest for each new component + keyboard test for the palette.
