| DC-011 | 2026-11-16 | User decision | **Local inference runtime: LM Studio (`lms`) instead of Ollama**, at the user's direction. LM Studio runs natively on the Windows host, so it gets direct GPU access, and serves an OpenAI-compatible API on `127.0.0.1:1234`. Containers reach it at `host.docker.internal:1234` (verified HTTP 200 from a container). Consequences: (1) no inference container in compose; the AI runtime is a host prerequisite in the runbook. (2) The model gateway (M04.02.01) and embedding adapter (M03.02.05) target the OpenAI-compatible `/v1` API, so Ollama, llama.cpp `llama-server` or vLLM stay drop-in alternatives (ADR-020/022 unchanged). (3) LM Studio is free to use but **closed-source**; the licence terms are recorded in `docs/spikes/local-models.md`. (4) The partial Ollama benchmark was stopped, and its numbers are not used. (5) **Licence constraint (found in M00.03.04):** the LM Studio Desktop App terms (version dated 2026-08-23) allow personal and internal-business use only, and forbid service-bureau, ASP and SaaS use. LM Studio is therefore a **local-development runtime only**. Any hosted deployment (ADR-002) must point `AI_BASE_URL` at a permissively licensed `/v1` server such as llama.cpp `llama-server`, Ollama or vLLM. (6) Defaults: embedding `google/embedding-gemma-300m` (768 dimensions), chat `google/gemma-3-4b`. The Gemma model-licence review is tracked for M08. Volume `ukos-models_ollama-models` (6 models, 12.64 GB) was deleted at the user's request on 2026-11-16, along with its stopped container and network. | Applied |
| DC-012 | 2026-11-16 | User decision | **Local OIDC provider: Dex v2.46.1** (`ghcr.io/dexidp/dex`, Apache-2.0, about 50 MB image), chosen by the user ("lighter option") over Keycloak (about 0.7–1 GB RAM).
