| DC-023 | 2026-11-19 | Design (M03) | Key decisions in `docs/architecture/m03-contracts.md`: (1) **PostgreSQL is the truth** for jobs, leases, checkpoints, revisions and the **publication pointer** (`document_publications`); Redis only wakes workers; RushDB is a rebuildable index. (2) **Deterministic revision and chunk ids** (`app/modules/ingestion/ids.py`, golden-value tests): re-runs and duplicate deliveries reuse the same revision; a new pipeline or embedding space creates a new one. (3) **Dedicated `ukos_worker` role (NOBYPASSRLS)**: workers find cross-org work only through six `SECURITY DEFINER` functions (claim, reap, three outbox ops, reconcile batch) that return ids; everything else runs under normal RLS after setting the org context. The role is created by the migration, not the init script (which only runs on an empty volume). (4) **Fencing**: every post-claim write is conditioned on `lease_owner` and `lease_epoch`, so a worker that lost its lease can't publish; an older version can never overwrite a newer publication. (5) **Interpretation of RushDB rule §7.2 (predicate by published revisions):** chunks carry a `published` flag and the adapter always filters `published = true` plus the workspace predicate (a boolean is index-friendly at scale, an IN-list of thousands of revision ids is not); the **PostgreSQL pointer stays the authority** and retrieval must revalidate every hit's `revision_id`, so the brief window where two revisions are flagged is safe. (6) The embedding space id is a hash of model, dimensions, both prefixes and a spec version (ADR-020). (7) M03 supports PDF, TXT, Markdown and HTML; other types end as `unsupported` (terminal), scanned PDFs as `no_text_extracted` (OCR is M06). (8) Two new compose services, `worker` and `dispatcher`; the local embedding server runs on the host. | Applied |
