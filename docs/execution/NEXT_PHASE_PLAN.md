# Next-phase plan (M11 to M17): approved roadmap features split into agent-sized tasks

Source: the user's decisions on the roadmap page (2026-11-20/21): 54 approved, 8 later, 8 undecided (see end). Feature ids (G2, C1, ...) refer to that page.
Rules for every task: read `docs/development/agent-rules.md`; lean tests (happy path + one cross-tenant check + one failure path); `scripts/dev/verify.sh` quiet; commit only your own paths; never push (coordinator pushes at milestone gates); no secrets or prompt/answer text in logs or audit.

## How tasks are made independent
- **One owner per path.** Each task lists the paths it owns. Shared files (`main.py`, `core/config.py`, `.env.example`, compose, `openapi.snapshot.json`) take additive edits only, and the openapi snapshot is regenerated by the coordinator after a wave merges (agents regenerate locally and note it).
- **Migrations are reserved by range** so agents never collide: M11 = 0012-0015, M12 = 0016-0019, M13 = 0020-0022, M14 = 0023-0028, M15 = 0029-0032, M16 = 0033-0038. A task that needs one states its number; the coordinator chains `down_revision` at merge.
- **Each task ships its own contract note** (10 lines in its milestone's `docs/architecture/m1x-contracts.md`) and a feature flag defaulting to off when behaviour changes (`FEATURE_X_ENABLED`).
- **Waves** group tasks with no mutual dependency; run a wave's tasks in parallel in worktrees, merge, verify, then the next wave.
- Sizes: S under 1 day, M 1 to 3 days, L over 3 days of agent work.

## Suggested order
M09 review + M10 deploy (in progress) -> **M11** gateway/usage/caching + **M12** eval foundation (parallel) -> **M13** observability -> **M14** security -> **M15** advanced eval + retrieval -> **M16** ingestion/platform -> **M17** production readiness and testing sprint (some M17 tasks can run earlier; marked).
Evals (M12) come before prompt or model changes so every later change is measured.
