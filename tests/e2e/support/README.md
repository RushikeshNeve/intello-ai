# End-to-end test support

## `embedding-stub.mjs` - fake OpenAI-compatible embeddings server

Dependency-free Node (20+) HTTP server standing in for LM Studio in end-to-end tests (M03.02.05).
It never logs request texts and sends `usage.prompt_tokens: 0` like LM Studio, so clients must
count tokens themselves.

```bash
PORT=18234 DIMENSIONS=768 node tests/e2e/support/embedding-stub.mjs
# prints: embedding-stub listening on http://127.0.0.1:18234 model=google/embedding-gemma-300m dimensions=768
```

Point the API/worker at it with `AI_BASE_URL=http://127.0.0.1:18234/v1` (from a container:
`http://host.docker.internal:18234/v1`, and start the stub with `HOST=0.0.0.0`). Wait for it with
`GET /health` (`{"status":"ok"}`).

| Endpoint | Behaviour |
| --- | --- |
| `GET /v1/models` | `{"data":[{"id": MODEL}]}` |
| `POST /v1/embeddings` | OpenAI shape; `input` is a string or an array of strings; returns `data[i].index`, `embedding`, `model`, `usage`. A different `model` in the request gives 404. |
| `GET /health`, `GET /__stats` | liveness; fault state and counters `{requests, failed, served, inputs}` |
| `POST /__control` | change fault state at run time (JSON, see below); `{"reset": true}` clears faults and counters |

Environment: `PORT` (18234), `HOST` (127.0.0.1), `DIMENSIONS` (768), `MODEL`
(`google/embedding-gemma-300m`).

Fault injection (initial value from the environment, changeable with `POST /__control` using the
lower-case key):

| Env | Control key | Effect |
| --- | --- | --- |
| `FAIL_FIRST=n` | `fail_next` | the next n embedding requests answer `FAIL_STATUS` (default 503) |
| `FAIL_STATUS` | `fail_status` | status for injected failures (503, 429, 400 ...) |
| `WRONG_DIMENSIONS=1` | `wrong_dimensions` | vectors have `DIMENSIONS-1` entries |
| `WRONG_COUNT=1` | `wrong_count` | one vector too few |
| `REVERSE_ORDER=1` | `reverse_order` | `data` returned in reverse order (indexes kept) |
| `DELAY_MS=n` | `delay_ms` | wait n ms before answering (timeouts) |
| `ECHO_MODEL=x` | `echo_model` | report model `x` in the response |

Example: `curl -X POST localhost:18234/__control -d '{"fail_next":2}'` makes the next two
embedding calls fail with 503, then succeed.

### Embedding algorithm and the golden file

The vectors are deterministic feature-hashing bag-of-words embeddings (documented in
`apps/api/app/modules/ai/embeddings/fake.py`; the Python `FakeEmbeddingClient` uses the same
algorithm). Texts sharing words are closer in cosine similarity, so end-to-end search tests get
meaningful rankings without a model. The stub hashes the text exactly as received; the real client
sends the model prefix (`title: none | text: ` for documents, `task: search result | query: ` for
queries) as part of the text, and the fake applies it the same way.

`apps/api/tests/ai/test_fake_and_golden.py` compares Python vectors with
`apps/api/tests/ai/golden/vectors.json`, generated by this stub. After a deliberate algorithm change
(edit `fake.py` and `embedding-stub.mjs` together) regenerate from the repository root:

```bash
node tests/e2e/support/embedding-stub.mjs --vectors apps/api/tests/ai/golden/cases.json \
  > apps/api/tests/ai/golden/vectors.json
```
